# Application sweep — October 7, 2026

## Scope and environment

Reviewed the desk, inventory, pipeline, lenders, reports, finance tools, settings, authentication, dealership and owner administration, imports, document scanning, PDF generation, AI routes, authorization hooks, calculations, dependencies, migrations and release configuration. Exercised sales, manager, administrator and platform-superuser paths with synthetic records on disposable local PocketBase databases. Production checks were read-only.

This records the defects found and the checks performed. It is not a claim that every possible input, browser, external service or security attack has been tested.

## Migration behavior

`1747900002_explicit_tax_override.js` adds a boolean field to `dealer_settings`. It enables existing positive overrides and leaves legacy/default zero overrides disabled because their former intent cannot be recovered from a numeric zero alone. An administrator who intentionally needs 0% must enable it explicitly.

The migration was exercised on a fresh seeded database and a SQLite backup of an older synthetic database. A positive 5.875% legacy override remained enabled, a default zero remained disabled, and running migrations a second time preserved the result. No production database was changed by this sweep.

`1747900003_unknown_inventory_mileage.js` adds a separate flag for missing mileage. New missing values persist as unknown, including VIN decode and imports. Editing an explicit numeric mileage clears the flag, including genuine zero. Existing recorded values are preserved; legacy zeros cannot be retrospectively classified as entered versus missing.

- All migrations applied to an empty throwaway database; a second run reported no new migrations. Upgrade testing retained the legacy positive tax override and distinguished new unknown mileage from a confirmed zero.
- Browser review found no new warning/error logs after the analytics/virtualizer fixes. Generating an HTML report in the ignored coverage directory left an open worksheet intact, confirming the development reload correction.

## Operational limits

- The production API health endpoint and app returned HTTP 200 during the sweep. The deployed build predates these changes.
- The production AI model catalog returned HTTP 200 and reported OpenAI, Anthropic and Gemini provider keys unconfigured. Live provider calls cannot be verified until an authorized operator configures a key. Mocked extraction and backend validation/authentication tests do not prove live model quality.
- Actual lender rate sheets were not provided. Synthetic programs exercise calculations; production samples remain unverified. A rules fit or readiness percentage is not an approval probability or a lender decision.
- OCR tests use deterministic recognition output. The scanner requires human confirmation because image quality, current-period/YTD layout and recognition accuracy vary.
- This sweep does not resolve counsel's review of legal language or certify transaction-specific tax/product contracting requirements.
- Accessibility tests cover serious/critical automated findings on the tested routes and themes; they do not replace a comprehensive assistive-technology audit.
